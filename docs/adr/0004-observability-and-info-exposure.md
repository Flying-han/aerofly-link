# ADR 0004: 可观测性与信息暴露——默认安静，诊断显式开启

- 状态: 已接受（2026-09-18）

## 背景

1. 发布版曾默认写三类诊断文件：`diag.log`（逐帧遥测/连接细节）、`fsd_packets.log`
   （位置报文全量字段）、`crash.log`（未捕获异常）。其中帧级日志每 50Hz 一条、
   常驻写盘，既有 I/O 开销也向本机任何读者暴露内部细节。
2. 协议原始报文（`>>>` / `<<<` 行）曾无条件渲染到用户可见的通讯日志。
3. 用户要求发布版不在控制台/可视化/逆向路径上暴露不必要的技术信息。

对 PyInstaller 打包的 Python 程序，字节码可被工具还原，**真正的防逆向不存在**；
能做且值得做的是控制信息暴露面与体积，而不是表演性混淆（pyarmor 等对成本/收益
不成比例，明确不做）。

## 决策

1. `diag.log`：默认**关闭**；设 `AEROFLYLINK_DIAG=1` 启用（排障时由维护者指导）。
2. `fsd_packets.log`：**删除**。其排查价值（PBH 编码验证）已由单元测试固化
   （`tests/test_fsd_client.py`、`tests/test_fsd_protocol.py`）。
3. `crash.log`：保留（异常路径低频写入，是唯一的现场还原手段）。
4. 协议原始报文仅当 `AEROFLYLINK_DEBUG=1` 时显示到通讯日志。
5. 空转路径的日志限频（重连前 3 次与每 20 次各一条，见 ADR 0005）。
6. C 重写客户端采用同一策略：release 构建默认安静，诊断需编译期/环境显式开启。

## 后果

- 排障第一步变为"设 `AEROFLYLINK_DIAG=1` 重现"，需写进 README 故障排查节。
- 用户机器上的默认痕迹：仅 `crash.log`（异常时）与 `settings.json`（无密码）。
